BLACKOUT 3.2 — Android / Capacitor

ЩО ОНОВЛЕНО У 3.2
- Прибрано дубльовані / застарілі функції панелі та діалогів.
- Додано версію схеми даних v3 і міграцію попередніх локальних записів та JSON-резервних копій.
- save() тепер повертає результат і показує попередження при помилці запису або переповненні сховища.
- Фото, як і раніше, зберігаються у localStorage як зменшені JPEG. При помилці запису попереднє фото відновлюється; перенесення фото через резервну копію поки не підтримується.
- Активну станцію не можна видалити до завершення сеансу; індекс поточної станції коригується після видалення іншої.
- Додано нативні Android-сповіщення для разових нагадувань і ковзної черги найближчих 12 повторних нагадувань про роботу генератора.
- Додано обробку системної кнопки «Назад»: закрити карту/діалог, повернутися на панель або вийти з застосунку.
- Поліпшено доступність кнопок на схемі потоків, повернуто масштабування сторінки.
- Розділено кольори акценту та статусу для Dark Premium / Light Minimal.

ФАЙЛИ
- index.html у корені репозиторію — джерело інтерфейсу.
- .github/workflows/android.yml — створює www/index.html і встановлює Capacitor 6, Bluetooth, Geolocation, App та Local Notifications плагіни.
- Збережено Android applicationId: com.blackout.log.
- Збережено localStorage key: blackout_v1.

ЯК ОТРИМАТИ APK
1. Відкрий Actions.
2. Обери workflow "Build APK".
3. Натисни Run workflow.
4. Після успішної збірки відкрий run і завантаж artifact blackout-apk.
5. Розпакуй artifact — app-debug.apk буде всередині.

ПЕРЕД ОНОВЛЕННЯМ APK
1. У чинному застосунку зроби резервну копію через Налаштування → Резервна копія.
2. Не видаляй старий застосунок, доки не збережеш копію в окремому місці.
3. Незмінний applicationId не гарантує встановлення поверх старого APK: Android вимагає сумісного підпису. Поточний workflow створює debug APK на новому runner, тож його підпис може відрізнятися. Якщо система не дозволяє оновити встановлення, спочатку переконайся, що резервна копія доступна, і лише тоді вирішуй питання видалення / перевстановлення.
4. Для безперешкодних наступних оновлень потрібен постійний release keystore і підписання всіх версій тим самим ключем.

ОБМЕЖЕННЯ ТА ПЕРЕВІРКИ
- Разові Android-сповіщення плануються Local Notifications plugin; Android може відкласти їх через режими енергозбереження, дозвіл сповіщень або обмеження точних будильників.
- Повторні нагадування плануються блоками по 12; після повернення застосунку черга синхронізується. Для тривалого фонового моніторингу знадобиться окрема нативна foreground-service архітектура.
- Фото все ще знаходяться в localStorage; IndexedDB / Filesystem та включення фото до backup — окрема майбутня задача.
- OSM / Nominatim і Bluetooth-протокол залишаються неперевіреними на реальних пристроях; не позиціонувати їх як production-ready без окремого тесту / юридичної перевірки.
- JavaScript пройшов синтаксичну перевірку; статично перевірено дублікати функцій, ключ localStorage, міграцію, нагадування, Back handler і доступність SVG. Фізичного тестування на Android цього коміту ще не виконано.
