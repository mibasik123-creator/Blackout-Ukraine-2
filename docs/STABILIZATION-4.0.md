# BLACKOUT 4.0 — технічний аудит і стабілізація (`proto/overview-4.0-v5.html`)

Дизайн v4 не змінено: розмітка, токени, SVG, композиція, анімації потоків, кільце, рядки пристроїв. Переписано лише JavaScript.

## Етап 1. Знайдені проблеми

| Рівень | Проблема | Статус |
|---|---|---|
| Critical | Генератор обирався пріоритетом, навіть коли мережа теж підтверджена — конфлікт джерел маскувався | виправлено: `feed='conflict'`, помилка, потоки не анімуються |
| Critical | Невідоме споживання будинку рахувалось як 0 у сумах мережі/генератора | виправлено: суми лише з виміряних складових, інакше «—»/«працює» |
| High | Не було станів OFFLINE / UNKNOWN — лише «свіже/застаріле» | виправлено: ONLINE / OFFLINE / STALE / UNKNOWN на кожне джерело |
| High | Немає перевірки меж SOC, NaN, від’ємних потужностей | виправлено: модуль валідації, некоректне → null + попередження |
| High | Немає попередження про перевищення 2400 Вт виходу | виправлено (вхід/заряджання станції не обмежується) |
| High | Ініціалізація падала б без Web Animations API | виправлено: CSS-анімація як запасний варіант |
| High | Анімації та твіни продовжувались у фоні | виправлено: пауза WAAPI/CSS, скасування rAF при `hidden` |
| Medium | FPS-лічильник працював завжди | лише в режимі розробника, вмикається кнопкою |
| Medium | Тестовий симулятор і панель у «продуктовому» коді | лише в режимі розробника (`BO_DEV_DEFAULT`, `?dev`) |
| Medium | Прямі звернення до DOM без перевірок | усі звернення через безпечні хелпери |
| Medium | Різні частини UI рахували показники окремо | один `computeBalance()` → усі компоненти |
| Low | Шрифт Inter не вбудований | не вирішено (див. нижче) |
| Low | Навігація «Пристрої / Аналітика / Система» без екранів | зафіксовано як окрема задача, кнопки не змінено |

## Архітектура

- **Telemetry Store** (`TelemetryStore`): останній зразок кожного джерела + час отримання; рендер ніколи не змінює час.
- **Data Validation** (`validate`): SOC 0–100, числа, невід’ємні потужності, перевищення 2400 Вт.
- **Energy Balance Engine** (`computeBalance`): чиста функція без DOM; єдине джерело всіх показників і потоків.
- **Flow Renderer**, **UI Renderer**, **Diagnostics**: лише читають результат.
- Публічний API для інтеграції: `BlackoutTel.set(source, sample)`, `BlackoutTel.offline(source)`.

## Енергетична логіка

Хто живить будинок (`feed`):
1. генератор і мережа підтверджені одночасно → **конфлікт** (помилка);
2. генератор підтверджений → генератор;
3. мережа підтверджена → мережа;
4. станція онлайн і виміряний вихід > 5 Вт, альтернатива не підтверджена → станція;
5. мережа підтверджено вимкнена, станція онлайн без виходу → немає живлення;
6. інакше → невідомо.

Потоки: генератор→будинок, генератор→станція, мережа→будинок, мережа→станція, станція→будинок, мережа→Tesla. Лінії станція→Tesla немає взагалі.
Будинок: лічильник (якщо є) або вихід станції під час відключення; інакше — «живлення є, потужність невідома» (рівна лінія без імпульсів).
Прогнози — тільки зі станції; якщо їх немає — «недостатньо даних для прогнозу».

## Тестування (фактично виконане)

- Автотести двигуна: `node proto/tests/engine.test.js` — 31 перевірка, 0 помилок (14 сценаріїв + межі й суперечності; тестується код саме з HTML).
- Браузер (Chromium, емуляція Pixel 7): 14 сценаріїв, ширини 360/390/430 без прокрутки й обрізання, 0 помилок у консолі.
- Фон: 0 викликів rAF, 6/6 анімацій на паузі, після повернення 6 працюють.
- 60 с перемикання сценаріїв: пам’ять 1,7→1,8 МБ, слухачі 18→18, анімації 6→6.
- Без Web Animations API і без `updatePlaybackRate`: без помилок, потоки рухаються (CSS-варіант).
- FPS при сповільненні CPU ×1/×4/×6: 61 кадр/с, найдовший кадр 17 мс.
- Продуктовий режим: панелі немає, лічильник FPS вимкнено, без даних — «Немає даних»; через `BlackoutTel` дані з’являються.
- Android: APK зібрано (окремий тестовий застосунок). **На реальному пристрої з Android WebView не перевірено.**

## Невирішене

- Перевірка на реальному Android WebView (потрібен телефон).
- Inter не вбудований — на Android буде Roboto.
- Розділи «Пристрої», «Аналітика», «Система» не реалізовані.
- У системі немає лічильника будинку; без нього лінії до будинку від мережі/генератора — без числа.
- Стан генератора в застосунку — із сесії генератора (сам генератор даних не передає).
- Підключення до реальних адаптерів BLE (Fossibot/Bluetti/EcoFlow/Tesla) і svitlo.live — етап інтеграції.
